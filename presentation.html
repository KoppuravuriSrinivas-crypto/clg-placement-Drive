01. Problem Analysis

Assessment Objective & Constraints

Core Mathematical Model

In Shamir's $(k, n)$ scheme, a secret $S$ is encoded as the constant term $c = P(0)$ of an $m$-th degree polynomial:

P(x) = a_m·x^m + a_{m-1}·x^{m-1} + ... + a_1·x + c
where m = k - 1
  • n = Total number of roots provided in the JSON input
  • k = Minimum number of points required to determine $P(x)$
  • Secret = Constant term $c = P(0)$

Assessment Constraints & Challenges

  • × Language Exclusion: Python is strictly prohibited.
  • • Variable Bases: Y-coordinates are given in non-decimal bases (base 2, 3, 6, 8, 12, 15, 16).
  • • Massive Integers: Decoded Y values exceed 64-bit bounds (up to $10^{20}$+). Standard double/int overflow.
  • ! Adversarial Points: Test Case 2 contains corrupted/imposter roots that invalidate naive point selection.
02. Engineering Architecture

Four-Stage Solution Pipeline

STAGE 1
Dynamic Base Parsing

Parses numeric and alphanumeric strings across arbitrary bases (up to radix 36) directly into unbounded BigInt primitives.

STAGE 2
Exact BigFraction Math

Maintains numerator and denominator separately using GCD reductions to prevent truncation errors during division.

STAGE 3
Consensus & RANSAC

Evaluates $\binom{n}{k}$ subsets to discover the true consensus polynomial that majority points satisfy.

STAGE 4
Outlier Isolation

Verifies every input point $(x_i, y_i)$ against $P(x_i)$. Any point where $P(x_i) \neq y_i$ is flagged as an imposter.

Pipeline: JSON Input → Base Decoder (BigInt) → Combinations Generator → Exact Rational Lagrange → Outlier Filter → Output c
03. Mathematical Rigor

Lagrange Interpolation & Fraction Safety

Lagrange Polynomial at x = 0

The secret $c = P(0)$ can be computed directly without solving full Gaussian matrices:

c = P(0) = ∑_{i=0}^{k-1} y_i · ∏_{j ≠ i} ( -x_j ) / ( x_i - x_j )

For $k$ points, the time complexity to find $c$ is $O(k^2)$, which is faster and cleaner than $O(k^3)$ Gaussian matrix inversion.

The Integer Division Trap & Fix

Critical Insight: While the final sum $c$ is guaranteed to be an integer, individual terms $y_i \cdot \ell_i(0)$ are fractions (e.g. denominators of 4, 8, 16)!

If integer division (yi * num) / den is performed eagerly, rounding truncation occurs at each step, producing invalid secrets.

✓ Our Solution: We created a lightweight BigFraction class maintaining (num, den) in reduced form via GCD throughout summation.

04. Adversarial Fault Tolerance

Detecting Imposter Points in Test Case 2

The Failure of Naive Selection

In Test Case 2, $n = 10$ points are provided, but only $k = 7$ are required.

Selecting the first 7 points ($x \in \{1, 2, 3, 4, 5, 6, 7\}$) includes the corrupted point $x = 2$, which yields a false secret:

c_{naive} = -6,290,016,743,746,469,796 ✗

This proves that outlier rejection is a mandatory requirement.

Combinatorial Consensus Rejection

Out of $\binom{10}{7} = 120$ possible subsets, the subsets formed exclusively from valid points all converge on the exact same secret:

c_{consensus} = 79,836,264,049,851 ✓
• Valid Set: $x \in \{1, 3, 4, 5, 6, 7, 9, 10\}$ (8 points)
• Imposters Identified: $x = 2$ and $x = 8$

07. Interview Defense

Anticipated Technical Questions & Answers

Q1: Why Lagrange interpolation over Gaussian elimination or Matrix inversion?
Answer: Gaussian elimination has $O(k^3)$ time complexity and requires computing all coefficients $(a_0 \dots a_{k-1})$. Since Shamir's secret is exclusively the constant term $c = P(0)$, Lagrange evaluated at $x = 0$ simplifies to an $O(k^2)$ closed-form summation, preventing matrix division rounding issues.
Q2: How did you handle arbitrary precision numbers beyond 64 bits without Python?
Answer: We leveraged native BigInt in JavaScript, System.Numerics.BigInteger in C#, and java.math.BigInteger in Java. We implemented custom base parsers that accumulate digits via Horner's scheme ($res \times b + digit$) to avoid standard parseInt 53-bit IEEE-754 precision clipping.
Q3: What is the algorithmic complexity of your outlier detection?
Answer: Combinatorial checking evaluates $\binom{n}{k}$ combinations. For $n=10, k=7$, $\binom{10}{7} = 120$ combinations, requiring $< 5$ milliseconds. For large $n$, we can substitute with RANSAC or Berlekamp-Welch error-correcting algorithms to achieve polynomial time.
